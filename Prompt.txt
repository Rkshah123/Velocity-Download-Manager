# 7. DOWNLOAD ENGINE — CORE REQUIREMENTS

The download engine is the most important part of this project.

It must be implemented as a real, independent, testable component.

## 7.1 Normal downloads

Support:

- HTTP.
- HTTPS.
- GET requests.
- Redirect handling.
- Server response validation.
- Filename extraction.
- Content-Length detection when available.
- Content-Type detection.
- Chunked responses.
- Unknown file sizes.
- Large files.
- Binary files.
- Documents.
- Archives.
- Software installers.
- Audio.
- Video.
- Other ordinary downloadable formats.

Do not restrict downloading based on file extension.

The engine must handle files based on their actual network response and server behavior.

## 7.2 Download acceleration

Implement segmented downloading using HTTP Range requests.

Requirements:

- Check whether the server supports byte ranges.
- Check whether the server permits concurrent range requests.
- Determine file size where available.
- Divide supported downloads into segments.
- Allow configurable connection counts.
- Maintain independent segment states.
- Write data to correct file offsets.
- Prevent overlapping writes.
- Verify segment boundaries.
- Handle failed segments.
- Retry failed segments safely.
- Combine the result correctly.
- Verify the final file size.
- Fall back to normal downloading when segmentation is unavailable or unsuitable.

Do not claim that multiple connections always make downloads faster.

Avoid overwhelming remote servers.

Provide configurable connection limits and sensible defaults.

## 7.3 Pause and resume

Implement genuine pause and resume functionality.

The system must:

- Stop active network operations safely.
- Preserve already downloaded data.
- Save segment progress.
- Persist resume metadata.
- Restore metadata after application restart.
- Validate remote file identity before resuming.
- Handle changed files.
- Handle expired URLs.
- Handle missing files.
- Recover incomplete downloads safely.

Use ETag and Last-Modified validators when available.

Use appropriate conditional range requests to prevent accidentally mixing different versions of a file.

Do not claim a download is resumable when the server does not support the necessary behavior.

## 7.4 Retry system

Implement:

- Configurable retry limits.
- Exponential backoff.
- Network failure detection.
- Temporary server error handling.
- Timeout handling.
- Connection recovery.
- Clear failure messages.

Do not retry permanent errors indefinitely.

## 7.5 Download integrity

Implement:

- File size verification.
- Correct segment boundaries.
- Safe finalization.
- Temporary files.
- Incomplete download cleanup.
- Optional checksum verification when a trusted checksum is available.

Never mark an incomplete or corrupted file as successfully downloaded.
